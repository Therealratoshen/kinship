# OSS autonomous-agent & open-source project failures — what they did wrong, and what Kinship does about it

**Date:** 2026-10-17 · **Method:** desk pass over primary sources (project READMEs at dated tags/branches, vendor announcement posts, CISA/CAIS notes, GitHub discussions) plus dated secondary coverage. Every external claim below is cited or marked `[UNVERIFIED]`. Reversal-visible: the "could be wrong" column is load-bearing, not decoration.

**Why this pass exists:** the owner asked what mistakes open-source autonomous projects have already made, so this repo can copy the failure shapes instead of re-creating them. Read alongside `AGENT-GOVERNANCE-LANDSCAPE-2026-10-17.md` (which covers the governance-tooling layer) — this file covers the *projects themselves*.

**Honest limit, stated first:** none of these projects had a shadow mode or an approval queue to retrofit. We can copy their failure shapes; we cannot copy their fixes, because for most of them there weren't any — the artifact was archived, rebranded, or forked away from them.

---

## The nine failure patterns

| # | Pattern | What actually happened (sourced) | Kinship's counter — already built, or added by this pass |
|---|---|---|---|
| 1 | **The demo that was never a product** | AutoGPT's own README at tag `v0.4.0` (2023): *"Auto-GPT is an experimental open-source application…"*, *"Not a polished application or product, just an experiment"*, *"Quite expensive to run, so set and monitor your API key limits"*. The project grew ~100k+ stars on that experiment `[UNVERIFIED: exact star count and date — secondary sources only]`, and by 2026-10-17 the master README is a platform pitch ("AI agents that finish the work", managed cloud + self-host + visual builder) — the demo repo had to become a commercial product or stay a demo. | The **phase-1 gate is a measurement, not a build** (`DECISIONS.md` D6, `pilots/shadow-mode/`), and the claim ceiling (PRD §2.3) bans the sentences a demo invites ("runs itself"). Evals were committed *before* anything can pass them. Installs, not stars, are the success metric (PRD §9). |
| 2 | **Autonomy without a budget = a cost with no stop** | The same v0.4.0 README shifts spend risk to the user: *"responsible for monitoring and managing your own token usage and the associated costs."* Community reports of agents looping until API credits ran out are abundant but anecdotal `[UNVERIFIED: no audited incident ledger exists]`. The direction is confirmed by the project's own warning. | FR-1.12: event-scoped, **rupiah-denominated** warn-then-hard-stop budgets wrapping LiteLLM (D14 candidate); `max_actions_per_run` with `truncated: true` and **no retry storm**; the number is deliberately unset (§12-Q9) until shadow mode produces one real figure. |
| 3 | **Goal-driven autonomy meets one destructive instruction** | **ChaosGPT** (2023-04): an AutoGPT fork publicly tasked to "destroy humanity" planned and posted on Twitter until the account was suspended; documented by CAIS's AI Safety Newsletter #2 and contemporaneous coverage (Vice, Futurism). The *agent* achieved nothing; the *ecosystem's* trust absorbed the hit. | The whole ladder. A member message is **data, not instruction** (§2.7); every member-facing class starts at `draft`; a fleet that cannot name its human refuses to boot (`needs.escalation_contact`); and no prompt can raise its own autonomy (`trust.raise-self` is structurally absent, Part 5). ChaosGPT's failure is the argument for the entire spec. |
| 4 | **The loop with no stopping condition** | **BabyAGI**: a naive task queue that plans forever with no definition of done; the original repo was **snapshotted and closed in September 2024** (*"All issues and commits were closed as of this transition"* — `yoheinakajima/babyagi_archive` README, read 2026-10-17), development restarted in a new repo. | The event-lifecycle state machine ends in `closed`; **one send per phase per origin**; `no_ghost_watchers` — a promise to follow up requires a persisted wake row, so nothing "plans" that can never act. |
| 5 | **The pivot that strands the community** | **GPT-Engineer → Lovable**: the OSS repo rebranded into a commercial app-builder (vendor rebranding post, 2025-01-13); the repo that thousands built on became a funnel for the hosted product. Lovable's commercial success is real and is not the criticism — the criticism is that the OSS artifact's future was decided by the product, and the community found out at the rebrand. | **D19 (this pass):** the product surface is disclosed up front — hosted product at shortcutsistem.com, OSS repo is the control plane, and the README's product-surface section commits to naming any boundary change on the day it happens. `fork_chain` + the powered attribution trail make forks creditable rather than disposable. |
| 6 | **The license flip, and the fork it deserves** | **HashiCorp** adopted BSL 2023-08-10 (vendor post); **OpenTofu** forked 2023-08-25 (fork announcement post) and is now the default in much of the ecosystem `[UNVERIFIED: adoption share]`. **Redis** relicensed 2024-03 (RSALv2/SSPLv1) → **Valkey** forked under the Linux Foundation; **Redis 8 re-opened under AGPL in May 2025** — and by 2026 redis.io itself hosts a "What is Valkey?" comparison post, which is a vendor acknowledging its own fork. The flip cost more than the license ever earned `[judgment, not sourced claim]`. | License is **Q4, owner's call** — MIT proposed but never printed as settled. D19 commits to **no silent flip**: any change goes through a dated `DECISIONS.md` row first. Structurally, the pack format is the forkable unit — the schema pin (`kinship/v1`) means a fork keeps running even if upstream moves. |
| 7 | **Strangling your own free tier to push the paid one** | **MinIO** removed the admin UI from the community edition (2025, reported 2025-06-19 by Blocks & Files; Cloudian's post calls it "bait and switch"); the project's own GitHub discussion **#21326** is titled *"It's not a feature issue, it's a trust one"* — the community said the quiet part. | D19's **self-hosted parity** statement: nothing in the OSS repo may be a crippled demo of the hosted product. The validator runs offline, dependency-free, no install step — by construction there is no "community edition" to degrade, because there is only one edition. |
| 8 | **The maintainer was the attack surface** | **XZ Utils**, CVE-2024-3094 (2024-03): a multi-year social-engineering campaign placed a maintainer (`Jia Tan`) beside a burned-out sole maintainer and shipped a backdoor; CISA's lessons post (2024-04-12) makes maintainer sustainability the headline lesson. This is not an agent failure — it is the supply-chain failure class D15/FR-1.14 exist for. | Pack trust presets fail closed, `bundled: true` is a claim only core packs may make, and the validator rejects `{code:'invariant_removed'}`. **Unsolved and recorded as a risk, not papered over:** this repo currently has one maintainer, and every named countermeasure assumes the human is reachable and rested. |
| 9 | **Stars as the success metric** | The 2023 cohort competed on GitHub attention; Paperclip's own stat (103,198 stars vs 472 watchers, PRD §9) shows what attention is worth as a *usage* measure. | Installs (real runs of the validator against a real pack), the `powered: auto-counted` attribution trail, and the pitch gate that requires one clean shadow event before AIClub is spent (D5). |

## What this pass changes in the repo

1. **D19** — product-surface disclosure (shortcutsistem.com) + the no-silent-flip and no-funnel commitments, written before the product exists, which is the only cheap time to write them. → `README.md`, `DECISIONS.md`.
2. **Q4 gains evidence**: the MinIO/Redis/HashiCorp row is the argument that the *disclosure discipline* matters more than the license text, because a fork is the community's real remedy and MIT permits forking. MIT stays the recommendation; the owner still decides.
3. **FR-1.12 / Q9 already cover the cost-stop failure** — no new requirement; the AutoGPT quotes go here as the failure-shape citation.
4. **The one-maintainer risk is named** (pattern 8) because every governance control in this repo assumes a reachable, sustainable human. Pre-committing to the mitigation is phase-2 work; naming the risk now is free.
